# インターネットへの公開手順

## 無料で公開する（おすすめ：Render）

Render の無料プランは常設のURLが持て、PCを切っていても遊べます。設定は `render.yaml` に入れてあります。

**制限**

- 受信が15分ないとサーバーが眠ります。次のアクセスで起こすのに1分ほどかかります
- 眠るとルームは消えます。接続中は画面が定期的に合図を送るので、誰かがつないでいる間は眠りません
- 無料プランはいつ再起動されるか分からず、再起動すると進行中のルームは消えます
- 無料枠は月750時間で、ワークスペース全体で共有します。使い切るか、通信量の無料枠を超えると、その月は止まることがあります

**手順**

1. GitHub に空のリポジトリを作る（公開でも非公開でも可）
2. `island-survival` フォルダを**単独で**リポジトリにして送る。親の `Cloude` フォルダは他のプロジェクトが入っているので送らない

   ```bash
   git init
   git add .
   git commit -m "最初の版"
   git branch -M main
   git remote add origin https://github.com/（ユーザー名）/island-survival.git
   git push -u origin main
   ```

3. [Render](https://render.com/) にアカウントを作り、GitHub と連携する
4. ダッシュボードの **New → Blueprint** でリポジトリを選ぶ。`render.yaml` が読まれ、無料プランのサービスが作られる
5. 発行された `https://island-survival-xxxx.onrender.com` を開いて、下の「公開後の確認」をする

`main` に push すると自動で更新されます。更新すると進行中のルームは消えます。

**遊ぶ前に：** 開始の少し前に誰かが一度URLを開いて、サーバーを起こしておくと待たずに済みます。

## もっと手軽に試す：自分のPCから一時的に公開

Cloudflare のクイックトンネルは、アカウントなしで自分のPCに一時的なURLを付けられます。Cloudflare はテスト用としており、稼働の保証はありません。PCを起動したままにする必要があり、URLは毎回変わります。公式の説明に WebSocket の記載はないので、まず試してください。

[cloudflared](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/) を入れてから、`island-survival` フォルダで次を実行します。

```bash
npm run build
```

```bash
npm start
```

別のターミナルで：

```bash
cloudflared tunnel --url http://localhost:5557
```

表示された `https://…trycloudflare.com` を友だちに渡します。この方法では全員が同じ接続元に見えるので、回数制限（下の表）は全員で共有します。

## 他のホスティング先を選ぶ場合の条件

このゲームのサーバーは、WebSocket の接続を持ち続け、ルームをメモリに置きます。

- **常時起動できるサーバー**が動かせる。リクエストごとに起動する形（Vercel や Netlify の関数など）は使えない
- **WebSocket** と **HTTPS** が使える
- **台数は1台に固定**する。2台以上にすると、同じルームの人が別のサーバーに分かれて対戦できない

Docker が使えるサービスでは `Dockerfile` をそのまま使えます（ポート `8080`、死活監視は `/healthz`）。

Docker を使わないサービスでは、次の2つを指定します。

- ビルド：`npm ci --include=dev && npm run build`
- 起動：`npm start`（環境変数 `TRUST_PROXY=1` も設定する）

## 環境変数

| 名前 | 既定値 | 内容 |
| --- | --- | --- |
| `PORT` | 開発 5557 / Docker 8080 | 待ち受けるポート |
| `TRUST_PROXY` | 開発は未設定 / Docker と render.yaml は `1` | サービスの中継サーバー越しに動くとき `1`。接続元IPの判定に使う |
| `ALLOWED_ORIGINS` | なし | 画面を別のドメインに置くときだけ、カンマ区切りで指定する |

## 入れてある守り

| 対象 | 内容 |
| --- | --- |
| 他サイトからの接続 | 同じドメインのページ以外からの WebSocket を断る |
| 合言葉の総当たり | ルーム作成と参加は、1つのIPから1分に20回まで |
| 送りすぎ | 1つの接続から10秒に100メッセージを超えると切断する |
| 接続数 | 1つのIPから30接続、全体で2000接続まで |
| ルーム数 | 全体で200ルームまで。誰もいないルームは30分で消える |
| メッセージの大きさ | 1件16KBまで |
| 霧の不正閲覧 | 判定はサーバーで行い、各プレイヤーに見えてよい情報だけを送る |
| 画面の配信 | CSP などのヘッダーを付ける。`dist` の外のファイルは読めない |

## 知っておくこと

- **更新や再起動でルームが消える。** ルームはメモリにしかありません。遊んでいない時間に更新してください。
- **席の記憶はタブごと。** スマホでタブを閉じると、そのゲームには戻れません（アプリの切り替えや再読み込みなら戻れます）。
- **アカウント機能はない。** 合言葉を知っていれば誰でも、開始前のルームに入れます。
- **通信量は少ない。** 圧縮後、1ターンあたり数KB程度です（5人・大マップで全員が採取した場合の実測で約4KB）。

## 公開後の確認

1. `https://（公開先）/healthz` が `ok` を返す
2. 違う回線の2台（スマホのモバイル回線とPCなど）で同じルームに入る
3. 招待URLが `https://（公開先）/?room=…` になっている
4. 予約を確定すると結果が再生され、次のターンに進む
5. スマホで再読み込みしても席と予約が残っている
